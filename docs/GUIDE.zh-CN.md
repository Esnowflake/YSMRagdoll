# YSM Ragdoll

[返回中文首页](../README.md) | [English](../README.en.md)

`ysmragdoll` 是面向 Minecraft 1.20.1 Forge 与 Yes Steve Model（YSM）的客户端布娃娃物理模组。
玩家死亡后，服务端只广播一份很小的死亡状态；安装模组的客户端从本机已经加载的 YSM 模型中
冻结网格、纹理和骨骼姿态，再使用 OpenYSM 的模型解析能力与 JBullet 创建独立物理尸体。
高级设置也可以直接用当前玩家模型创建本地测试布娃娃，不需要玩家死亡或服务端发送快照。

当前版本为 `0.5.26`。这一版本已经包含真实骨骼尺寸碰撞箱、关节角度限制、方块碰撞、玩家推动、
爆炸冲击、地面摩擦、方块填入后的推出保护、设置界面和调试碰撞箱。布娃娃不会继续读取死亡
玩家的动画，也不是原版玩家模型的替身。

## 安装方式

构建后应使用带依赖的文件：

```text
build/libs/ysmragdoll-0.5.26-all.jar
```

普通玩家直接从上方 Release 下载对应的 `-all.jar` 即可；自行构建时使用上述路径的产物。
仓库内 `release/` 目录保留的是早期 `0.5.19` 成品，当前安装包以 GitHub Releases 为准。

不要使用体积更小的 `ysmragdoll-0.5.26.jar` 作为普通游戏发行包，因为它没有包含运行物理所需的
JBullet 和 vecmath Jar-in-Jar 依赖。

### 单人游戏

在同一个 Minecraft 1.20.1 Forge 实例中安装：

- `ysmragdoll-0.5.26-all.jar`
- 兼容的 YSM 模组，例如已经验证的 YSM 2.6.5
- 玩家要使用的 YSM 模型资源

单人游戏的集成服务端会发送死亡快照，当前客户端负责模型捕获、物理和渲染。

### 多人游戏

服务端安装 `ysmragdoll` 后，才会在玩家死亡时发送快照。服务端不加载模型、不运行 JBullet，
也不保存任何尸体实体。

| 安装情况 | 结果 |
| --- | --- |
| 服务端安装；客户端安装本模组和 YSM | 客户端能看到并模拟布娃娃 |
| 服务端安装；客户端未安装本模组 | 可以正常加入，但看不到布娃娃 |
| 服务端未安装；客户端安装本模组 | 不能自动生成死亡布娃娃；高级设置仍可手动创建本地测试布娃娃 |
| 客户端安装本模组但没有 YSM | 可以运行，但无法捕获 YSM 模型，会在日志中说明原因 |

网络通道接受远端完全缺失，`mods.toml` 也使用 `IGNORE_ALL_VERSION`，因此本模组不会强制所有客户端
安装。已经安装本模组的一端必须使用协议 `2`；旧版通道不会被当作兼容端接受，避免收到无法解码
的新数据包。每个客户端独立读取自己的模型缓存并计算物理，所以不同客户端看到的姿态不保证
逐帧一致。

本工程不会自动复制或删除游戏 `mods` 目录中的任何文件。

## 工作原理

### 1. 服务端死亡快照

`ServerDeathEvents` 在服务端玩家死亡时创建 `PlayerDeathSnapshot`，内容只有：

- 实体编号和玩家 UUID；
- 死亡位置；
- 线速度；
- 身体朝向。

数据包只发送给正在追踪该玩家且声明了本模组网络通道的客户端。模型文件、纹理、骨骼数组和
刚体状态都不会经过网络。

### 2. 独立 YSM 模型快照

客户端收到死亡状态后，`OpenYsmModelAdapter` 在旧玩家实体仍有效时调用一次 YSM 玩家渲染流程。
可选 Mixin 在 YSM 2.6.5 最终提交网格之前捕获：

- YSM 网格对象引用；
- 每根骨骼 12 个浮点数的主变换数组；
- 辅助状态数组；
- 纹理、RenderType、颜色和透明度；
- 尸体根 PoseStack 到 YSM 网格之间的相对矩阵。

网格和纹理是只读资源，可以由尸体共享；骨骼变换数组必须为每具尸体单独复制。快照成功后，
后续渲染直接重放底层网格，不再调用活玩家的 capability、动画控制器或 `tickModel()`。因此玩家
复活、跑动、挥手或转头都不会驱动旧尸体。

首次捕获使用独立矩阵栈和丢弃顶点的临时缓冲。每次请求临时缓冲都会得到独立的顶点接收器，
使附加渲染层可以通过原版 `VertexMultiConsumer` 合并多个接收器，避免 `Duplicate delegates`
异常在网格捕获前中断渲染。捕获/重放渲染器的首次异常会记录完整堆栈。

### 3. OpenYSM 模型数据解析

物理模块先从捕获到的运行时网格中读取骨骼名称、父子层级、枢轴和可用顶点。官方 YSM 2.6.5
运行时网格缺少完整立方体列表时，`OpenYsmGeometryLoader` 会按 OpenYSM 的规则尝试补齐：

1. 根据当前 YSM capability 的模型标识查找本地模型；
2. 优先处理 `crypto=3` 的 `.ysm` 文件；
3. 使用 OpenYSM 的 CityHash、MT19937、XChaCha20 与 YSM Zstd 头还原进行解密；
4. 使用 OpenYSM 二进制反序列化器读取真实面顶点；
5. 普通模型则读取 `ysm.json` 与 Bedrock `main.json`；
6. 按骨骼名称和枢轴签名选择匹配度最高的几何，匹配不足时拒绝套用其他角色尺寸。

解析结果按网格对象使用弱键缓存，只发生在第一次遇到该模型时，不进入逐帧渲染和 120 Hz
物理热路径。无法取得精确几何时会使用骨骼枢轴估算尺寸；连躯干都无法识别时则保留静态快照，
不会因为物理初始化失败而让模型消失。

### 4. 刚体与关节

当前最多从模型中映射 14 个主要部位：

```text
躯干、头部
左/右上臂、左/右前臂、左/右手
左/右大腿、左/右小腿、左/右脚
```

每个部位使用模型真实几何包围盒生成旋转盒刚体，碰撞尺寸统一收缩到计算值的 `95%`，以减少
装饰网格和相邻关节处的误碰撞。头部使用真实头部包围盒的最短边生成居中的正方体，头发、帽子
等装饰允许穿模，不会把长发外轮廓当作头部刚体。

父子刚体使用 `Generic6DofConstraint`：平移轴全部锁定，旋转轴按人体关节限制。肩、髋和颈部
允许多轴转动；肘和膝主要允许单轴弯曲；手脚保留较小角度。布娃娃肢体之间的自碰撞关闭，避免
相邻盒重叠与锁定关节互相挤压造成持续抽动；各肢体仍通过关节完整连接并独立运动。

### 5. 物理解算与方块碰撞

所有客户端布娃娃共享一个 JBullet 世界：

- 重力为 `-9.81`；
- 渲染帧时间累积后以固定 `120 Hz` 子步推进；
- 单帧最多追赶 8 个子步，最长只接收 50 ms 帧间隔，避免暂停恢复后瞬间追帧；
- 约束求解迭代次数为 20，并启用 split impulse；
- 每 tick 更新每具布娃娃水平 3 格、垂直 4 格范围内的方块碰撞；
- Minecraft `VoxelShape` 会转换成一个或多个静态盒刚体；
- 方块弹性为 0，布娃娃仅和方块碰撞，不和其他布娃娃或自身肢体碰撞。

离散碰撞留下明显地面穿透时，系统会去除继续朝方块内部的速度，并把整具布娃娃一起向上纠正。
不会只移动头或腿，因为单肢体修正会拉伸关节并在下一步释放为异常弹跳。

如果玩家在布娃娃所在位置放置新方块，缓存会立刻加入新方块碰撞体，并在 20 tick 内持续检查
重叠，将整套刚体逐步推出到方块上方，防止尸体永久卡在新填入的方块中。

### 6. 玩家推动

玩家推动作用于物理刚体。易推动指数小于 `100` 时沿用渐进水平冲量响应：

- 使用玩家上一 tick 到当前 tick 的扫掠范围，降低快速移动穿过碰撞检测的概率；
- 接触余量很小，不会扩大布娃娃自身碰撞箱；
- 玩家主动向前或横移时才推动，站在模型内后退离开不会把尸体拖走；
- 推动响应约 55% 分配给整套刚体，约 45% 施加到实际接触肢体；
- 共同响应让尸体整体可移动，局部响应让手脚和躯干姿态能随接触改变；
- 推动后的短时间内清除正向竖直速度，减少水平推动被地面接触转换成原地起跳。

易推动指数为 `100` 时，改为优先满足本地玩家碰撞箱的强制分离响应：

- 使用玩家当前实际碰撞箱与各肢体旋转盒进行凸体扫掠和穿透检测；
- 玩家移动命中肢体后，把剩余推动位移传递给整具布娃娃，并匹配接触方向上的玩家速度；
- 在客户端 tick 中检查玩家移动和重叠，纠正重叠并调整接触方向速度；当前没有在每个物理子步调用反向肢体扫掠；
- 分离时整套刚体共同平移，避免单独拉动肢体造成关节拉伸；
- 玩家死亡、旁观或切换姿态时重置追踪；超过每 tick 8 格的移动按传送处理，只纠正终点重叠。

该模式优先保证布娃娃让开玩家，只影响当前客户端的物理布娃娃，不会改变玩家运动，也不会推动
其他客户端的模拟结果。贴墙、狭窄空间中的方块碰撞与玩家挤压效果仍需游戏内验证。

躯干局部轴采用不同角速度保留率并限制角速度，使侧翻比头脚翻滚更容易延续。当前没有躯干前后倾角的强制扶正或 ±30° 姿态限制，也不会主动给躯干追加侧倒力。

### 7. 爆炸冲击

服务端监听 Forge 的 `ExplosionEvent.Detonate`。TNT、普通/闪电苦力怕以及调用原版
`Level.explode`/Forge Explosion 流程的模组爆炸都会被识别；完全绕过 Explosion 事件、只自行造成
伤害或传送实体的特殊模组效果不会被自动识别。

爆炸数据包只包含中心坐标和原始威力，并广播给爆炸所在维度中声明了协议 `2` 的客户端。客户端
只处理自己当前持有的布娃娃：

- 使用原版实体爆炸范围，即原始爆炸半径的两倍；
- 按每个肢体碰撞盒边缘到爆心的距离进行线性衰减；
- 对每个肢体分别计算方向和质量相关冲量，使关节产生真实的折叠、翻滚和上抛；
- 使用爆心到肢体中心的方块射线近似原版遮挡，完整墙体后的尸体不会被穿墙推动；
- 爆炸会清除玩家推动阶段的防起跳状态，因此允许合法的向上冲击；
- 爆炸快照保留 1 秒，覆盖“爆炸先触发、玩家随后死亡、物理尸体下一帧才创建”的事件顺序；
- 爆炸威力读取、服务端事件和单具尸体冲量都有异常隔离，兼容问题只跳过本次响应，不中断爆炸或
  服务端 tick。

爆炸威力通过 Forge 的混淆安全反射读取；读取失败时使用受影响方块的最远范围作为后备，空中没有
受影响方块时使用保守默认值。工程不再通过 Mixin 修改原版 `Explosion` 类。

### 8. 物理姿态回写

创建刚体时保存 `boneToBody = inverse(initialRigidWorld) * initialBoneWorld`，包含几何中心、
骨骼枢轴、完整父级变换和根矩阵的缩放、镜像。后续使用 `currentRigidWorld * boneToBody`
恢复目标骨骼世界矩阵，不再从刚体旋转和骨骼缩放猜测绑定关系。碰撞盒尺寸同时转换到刚体
坐标系，调试线框、推动检测和地面校准统一读取这一尺寸。

回写按父级优先进行：先还原父骨骼的实际渲染矩阵，再反算子骨骼的局部变换。骨骼平移参数
使用像素，因此从方块单位回写时乘以 16；旋转按 Z/Y/X 顺序还原，缩放按矩阵列拆分并保留
镜像符号。没有刚体的中间骨骼、装饰骨骼和隐藏骨骼保留捕获时的局部参数。

### 9. 碰撞箱与渲染层的绑定状态

本次源码修复了平移回写缺少 16 倍单位转换、非等比缩放按行拆解、初始绑定丢失根缩放/镜像，
以及组合旋转的欧拉角还原问题。物理世界转回模型时使用与实际渲染相同的根矩阵，避免根变换
被重复施加。渲染 XYZ 偏移仍是人为附加的视觉偏移；验证时请将渲染和碰撞六个偏移都设为 0。

新增 `BoneBindingTest` 覆盖平移/旋转/镜像往返、多层父子骨骼、独立肢体旋转、整体地面修正、
碰撞世界平移、缩放后的盒尺寸和隐藏骨骼。测试通过后仍需要在官方 YSM 2.6.5 和实际模型中
检查死亡、倒地、玩家推动及爆炸翻滚。此前用户已经反馈模型错位已修复；这不代表所有模型均完成验证。手动创建功能仍需在实际游戏环境验证，模型捕获问题仍是独立问题。

碰撞箱仍按既有规则收缩为 95%，头部仍使用最短边正方体，故线框不会与模型外表面逐顶点重合；
应检查的是部位中心和运动是否同步。精确几何不可用时，枢轴估算箱也不能视为模型真实外轮廓。

非等比缩放父骨骼与独立旋转的子刚体可能形成剪切矩阵，YSM 的平移/旋转/缩放参数无法精确
表示任意剪切。这种情况下保持物理部位几何中心绑定，形状和旋转采用近似；该限制不应通过
整体 XYZ 偏移掩盖。

### 10. 手动创建与性能测试

高级设置按钮调用 `ClientRagdollManager.createFromCurrentPlayer()`。它读取本地玩家当前的位置、
身体朝向和速度，构造与死亡流程相同的数据载体，但不调用服务端事件或网络发送。玩家必须存活且
不是旁观者；数量上限为 0 时直接返回提示。

每次点击都独立调用 `OpenYsmModelAdapter.capture()`，获得新的骨骼数组副本。它不进入
`RECENT_DEATHS` 去重表，所以站在同一个位置连续点击也不会被当成重复死亡。捕获不成功时当场
报告失败，不进入延迟重试队列，也不会因此淘汰已有布娃娃；用户可以等模型加载好后再次点击。

捕获成功后，通过共享的 `promote()` 执行数量限制和加入列表，再立即调用 `initializePhysics()`
完成骨架解析、刚体/关节创建和首次姿态回写。正常死亡在 tick 中调用同一个物理初始化方法，
两条路径的物理、渲染和资源清理行为保持一致。手动创建不重放此前缓存的爆炸，但能受到创建之后
新发生的爆炸影响。骨架无法识别时保留静态快照，并明确报告它不是物理布娃娃。

按钮使用已保存参数，不会暗中保存界面草稿。默认上限为 2，第三次成功创建会淘汰最早的一具；
做多具性能测试时，应先在常规设置提高上限并应用，可调最大值仍为 10。默认寿命20秒，持续测试
时也要主动调整寿命或手动清除模式。设置页不暂停单人游戏，模型生成后可以立刻模拟，页面也保留
以便继续点击。界面的成功提示是点击当时的计数，长期性能数据以日志中的实时数量为准。

### 11. 坐标与矩阵契约（修改姿态代码前必读）

采用列向量，矩阵乘积右侧先作用。模型几何顶点、刚体长度和世界位置采用方块单位；骨骼枢轴和
数组中的平移采用像素，16像素为1方块。每根骨骼12个浮点数中，0–2是弧度旋转，3–5是像素平移，
6–8是缩放，其余参数保留捕获值。X平移的符号与Y、Z不同。

设像素枢轴为 p，像素平移为 t，YSM 正向局部矩阵为：

```text
L = T((px-tx)/16, (py+ty)/16, (pz+tz)/16)
    × Rz(rz) × Ry(ry) × Rx(rx) × S(sx,sy,sz)
    × T(-px/16, -py/16, -pz/16)
```

`BonePoseMath.local()` 是该规则的公共实现，初始骨架计算与姿态回写后的实际矩阵重建共用它。
不能把刚体世界中心直接写成骨骼平移，因为几何中心与旋转枢轴通常不是同一个点。

设初始骨骼世界矩阵为 G0，初始刚体世界矩阵为 B0，当前刚体世界矩阵为 Bt，则：

```text
K  = inverse(B0) × G0          固定绑定，存入 BodyPart.boneToBody
Gt = Bt × K                   当前目标骨骼世界矩阵
L目标 = inverse(P) × inverse(A) × Gt
```

A 是当前实际渲染根矩阵，P 是父骨骼相对于该根的实际累计矩阵。根位移只计入一次，相机变换不
固化到 K。初始刚体原点位于几何中心 c 的世界位置，因此 K×c 为刚体局部原点，Gt×c 为当前刚体
中心；这就是模型部位与物理中心同步的依据。整体地面推出改变 Bt，K 保持不变。

回写采用父级优先顺序。每根物理骨骼完成参数分解后，使用真实写回值重建矩阵，再以此计算它的
子骨骼，避免父级分解误差继续引起子部位中心漂移。没有独立刚体的骨骼保留初始局部参数，隐藏
骨骼的零缩放也保留；父矩阵不可逆时不强行求逆。

JOML 的 mXY 中 X 表示列。分解缩放时按列长度计算并按列除以缩放，结合初始缩放符号与行列式
保留镜像。旋转从矩阵显式还原为 Z/Y/X，并处理接近万向节锁的情况。按实际将写回的线性矩阵 H
重新校准几何中心，设 q=p/16、u=L目标×c：

```text
d  = u - H × (c - q)
tx = (qx - dx) × 16
ty = (dy - qy) × 16
tz = (dz - qz) × 16
```

这样重建后的局部矩阵会把 c 送到目标 u，即使非等比父级引入无法完全表示的剪切，也优先保持
几何中心绑定。任意剪切不能由YSM的平移/旋转/缩放数组精确表示，不能承诺全部顶点刚性重合。

Bullet只接受正交右手的刚体旋转，创建时正交化基向量，剩余变换保留在K中。碰撞盒的模型空间
半尺寸 h 按 `h' = abs(K的3×3线性部分) × h` 投影到刚体局部轴，BoxShape、调试线框、地面校准
和推动检测统一使用 h'。95%收缩和头部方盒规则仍然有效；对齐不代表碰撞箱等于可见外轮廓。

### 12. 所有权、线程与后续维护

网络处理通过客户端任务队列进入主线程；GUI点击、客户端tick与世界渲染也在客户端线程执行。
这些路径共用模型捕获和物理状态，不能直接从后台线程调用。捕获首次可能涉及反射、文件读取和
解密，因此首次创建耗时与后续缓存命中的创建耗时应分别评估。骨骼数组每具独占，资源网格和纹理
共享；结束模型捕获后不继续持有玩家实体作为渲染来源。

`ClientRagdollManager` 持有正式列表、有限重试队列、死亡去重表、1秒爆炸缓存和共享物理世界。
寿命使用墙上时钟，手动清除开启时跳过寿命删除；数量上限始终优先。手动右键选择采用5格射线与
躯干附近的选择球，并通过方块射线限制遮挡，不是逐三角形拾取。区块未加载时隐藏并暂停整具物理
布娃娃，重新加载后恢复；断线、世界卸载、维度切换和资源重载则清空列表、约束、刚体及骨架缓存。

主要修改入口：

| 要修改的行为 | 主要代码 | 必须保持的约定 |
| --- | --- | --- |
| 默认参数、范围 | YsmRagdollConfig | 与界面校验、语言描述及本表同步，保留已有合法配置 |
| 设置入口、按键 | RagdollKeyMappings / ClientRagdollEvents | UNKNOWN默认值、IN_GAME上下文、清空残留点击，只有一个界面创建入口 |
| 设置布局、测试按钮 | YsmRagdollSettingsScreen | 草稿与立即操作分离，换行、滚动和状态提示不重叠 |
| 创建、数量、清理 | ClientRagdollManager | 测试创建不参与死亡去重，数组独占，刚体和约束成组释放 |
| YSM版本兼容 | OpenYsmModelAdapter / Ysm265MeshCaptureMixin | 当前针对官方2.6.5混淆签名，不能将新版官方源码直接当作同一接口 |
| 模型几何和骨骼映射 | OpenYsmGeometryLoader / YsmSkeletonExtractor / RagdollDefinition | 枢轴像素、几何方块；缓存只复用结构，新尸体重新计算死亡姿态 |
| 刚体与渲染对齐 | BonePoseMath / PhysicsRagdoll | 固定绑定K、正向与反向单位一致、父级实际矩阵优先 |
| 玩家推动、环境碰撞 | PlayerCollisionResponse / ClientPhysicsWorld / BlockCollisionCache | 主调用频率与测试一致，整组平移，尺寸与BoxShape一致 |
| 爆炸 | ServerExplosionEvents / ExplosionImpulseSnapshot / PhysicsRagdoll | 协议变更同步两端，遮挡与冲量在客户端算 |
| 性能日志 | ClientPerformanceLogger / ClientIntensiveLogger | 密集补采样不等于真实100 Hz独立物理状态；getFrameTime是插值比例，不是帧耗时 |

`build.gradle` 只从本地OpenYSM编译JAR提取必要算法、Zstd和二进制解析类，JBullet与vecmath通过
Jar-in-Jar打包，不包含整个YSM模组。`YSMFolderDeserializer` 在本项目中仅为二进制解析器提供
动画类型映射；若未来适配真正的OpenYSM运行时，需要检查同包同名类冲突，不能据此宣称已兼容。

维护时先跑 `BoneBindingTest`、`CaptureBufferTest`、`PlayerCollisionResponseTest` 和
`SettingsScreenLayoutTest`。自动测试不能替代YSM运行时验证：实际检查未绑定时不弹窗、绑定后
按键打开、聊天时按键不残留、连续点击每次创建、上限淘汰、20秒清理、复活后旧尸体独立、模型
缺失错误提示，以及单人和多人环境中的物理与资源重载行为。性能测试应记录模型、当前数量、
物理数量、配置和是否开启密集日志，避免把静态快照或日志开销当成正常物理负载。

## 设置界面

默认快捷键为未绑定（UNKNOWN），只有玩家在 Minecraft 控制设置中主动绑定“打开YSM布娃娃设置”，回到游戏并按下该键时才打开页面。0.5.23 移除了原有客户端命令和模组列表配置入口。

快捷键使用 IN_GAME 冲突上下文，当前必须有世界和玩家且没有其他 GUI；每 tick 清空按键点击队列，其他界面中的残留点击不会在关闭界面后弹出设置。按 Esc 返回游戏。设置页面不暂停单人游戏，使测试布娃娃在页面打开时也继续模拟和计时。

设置保存在当前游戏实例的：

```text
config/ysmragdoll-client.toml
```

设置界面左侧是“常规”“高级”“布娃娃管理”和“测试”分类，右侧显示当前分类的内容。所有数字设置都通过文本框手动输入，
不使用滑块；越界值会标红并留在当前页面等待修正。

底部按钮遵循标准设置界面语义：确定会保存并退出，应用会保存但留在页面，取消和 Esc 会放弃自上次
保存以来的修改并退出。

### 常规设置

| 设置 | 范围/默认值 | 行为 |
| --- | --- | --- |
| 布娃娃存在时间 | `0` 到整数上限；默认 `20` 秒 | `0-10000` 表示对应秒数，大于 `10000` 表示永久 |
| 手动清除 | 默认关闭 | 开启后忽略存在时间，可空手右键清除；数量上限、虚空和世界卸载清理仍生效 |
| 数量上限 | `0-10`；默认 `2` | 优先级最高；满额后生成新尸体会删除最早的一具；设为 0 会清理已有尸体并停止创建 |

“永久”只表示当前客户端世界与资源会话内不按时间删除。断开服务器、切换世界/维度或 YSM 资源
重载时仍会清理尸体。数量上限始终高于永久和手动清除。

### 布娃娃管理

实时显示本客户端当前世界内的布娃娃数量，以及每具布娃娃的编号、玩家 UUID 前八位和消失倒计时。
计时使用与实际清理相同的创建时间和已应用配置，剩余秒数向上取整。开启手动清除后，在倒计时原位置
显示“已开启手动清除”；存在时间大于 10000 秒时显示“已设置永久存在”。列表支持滚动，数量变化后自动更新。

物理布娃娃的躯干刚体中心低于世界 Y=-64 时自动清除，静态快照使用生成位置判定。阈值为严格小于，
Y=-64 本身不清除；碰撞偏移和渲染偏移不影响该判定。此规则在所有维度均生效，也适用于手动清除和永久模式。
删除会释放刚体、关节及不再使用的共享物理世界。

### 测试：牵引模式

默认关闭。在“测试”分类点击“牵引模式”立即切换并保存；这是立即操作，不受底部“取消”影响。
开启后主手拿木棍，瞄准实际肢体碰撞箱，按住使用键（默认右键）牵引，松开释放。使用细青绿色光束连接
手部附近与实际抓取点。滚轮向上推远、向下拉近，每格 0.5 方块，距离范围 1.5–12 方块；抓取时滚轮
不切换快捷栏。没有命中时不会创建约束或光束，需要松手后再次尝试。

0.5.26 可通过“牵引线力矩”调整实际牵引：0 禁用，1–99 为有限力的软牵引，100 为刚性跟随。
保留重力、地形碰撞、关节防拉伸和原有自动清理规则。
移动中松开右键可顺势释放，整具质心速度上限为每秒 6 格；不会根据未实现的目标位移累积抛出速度。
射线和目标点会检查地形遮挡。松手、关闭模式、切换物品、打开界面、死亡、进入旁观模式、目标删除或
所在区块卸载时释放。开启且主手持木棍时接管使用键，避免同时触发方块或副手交互。
该功能仅作用于本客户端布娃娃，不发送牵引网络包；不包含冻结和旋转快捷键。
配置键仍为 `gravityGunMode`，保留已有开关设置。

### 高级设置

| 设置 | 范围/默认值 | 行为 |
| --- | --- | --- |
| 创建一个布娃娃 | 点击按钮 | 按当前玩家模型立即创建一具本地测试布娃娃，使用已保存设置，遵守数量上限和清除规则 |
| 布娃娃易推动指数 | `0-100`；默认 `90` | 小于 100 时决定渐进推动响应速度；100 时强制让开本地玩家碰撞箱并传递推动位移 |
| 地面摩擦力 | `0-100`；默认 `20` | 数值越高，整体水平滑动越快停止；保留肢体角速度，不会把四肢锁死 |
| 爆炸推动指数 | `0-100`；默认 `50` | 0 完全忽略爆炸推动；50 为标准强度；100 为标准强度的两倍 |
| 显示物理碰撞箱 | 默认关闭 | 显示每个肢体参与 JBullet 的旋转线框，不改变物理 |
| 密集测试 | 默认关闭 | 开启后以目标 100 Hz 采样 FPS、布娃娃刚体和骨骼姿态，写入独立日志 |
| 渲染 XYZ 偏移 | 每轴 `-4.0` 到 `4.0` | 只移动布娃娃模型渲染，单位为方块 |
| 碰撞箱 XYZ 偏移 | 每轴 `-4.0` 到 `4.0` | 平移整个物理世界、布娃娃刚体和方块缓存，单位为方块 |

碰撞偏移和渲染偏移相互独立。调试时应先打开碰撞箱，以方块表面是否与真实刚体接触为依据调整
碰撞偏移，再用渲染偏移校准模型。正常使用建议保持六个偏移均为 `0.0`。

“密集测试”只建议在复现问题时临时开启。它会在 `ysm-ragdoll-logs/ysm-ragdoll-intensive.log`
中追加约每 10 ms 一行，包含采样单调时钟、游戏 FPS、帧时间、尸体数量、每具尸体的躯干刚体
位置/旋转/线速度/角速度，以及捕获骨骼数组中的 XYZ 姿态值。采样在渲染线程执行，低帧率时会
补写错过的采样时刻，但单次最多补写 20 行以避免日志写入反过来拖慢游戏。关闭设置或断开世界
后会重置采样时钟；日志文件不会发送到服务端。

“创建一个布娃娃”位于高级设置顶部。点击后页面保留，结果提示显示当前总数与物理布娃娃数；捕获失败、数量上限为 0、没有可用玩家或只能创建静态模型时给出相应提示。此按钮执行立即操作，不保存设置草稿，也不会被取消按钮撤销。修改数量、寿命或物理参数后，先点“应用”再创建。

标签按实际字体宽度换行，输入框与下一项之间保留独立间距。宽窗口的高级内容按两列排列，
窄窗口自动改为单列；内容超高时可用滚轮、拖动滚动条或 PageUp/PageDown 翻页，底部按钮保持固定。
调整窗口大小会保留未保存的输入，错误提示也会独立预留空间。

默认参数为：数量上限 2、存在时长 20 秒、手动清除关闭、易推动 90、地面摩擦 20、爆炸推动 50、碰撞箱显示关闭；密集测试关闭，六轴偏移为 0。默认值用于新配置或缺失的配置项，已有合法的玩家配置和主动绑定的快捷键会保留，不会在升级时强制覆盖。旧配置如需使用新默认值，请在界面手动修改并应用。数量可调范围仍为 0–10，超范围值由 Forge 校正。

## 日志与排查

开发运行配置会把关键日志写入工程目录：

```text
ysm-ragdoll-logs/ysm-ragdoll.log
```

开启高级设置“密集测试”后，另有：

```text
ysm-ragdoll-logs/ysm-ragdoll-intensive.log
```

该文件专门用于分析布娃娃躯干为什么保持直立、翻倒或发生穿透。每行以 `[INTENSIVE]` 开头，
可按 `player=`、`bodyPos=`、`bodyBasis=`、`velocity=`、`angular=` 和 `bones=` 搜索。日志只在
开关打开时生成和追加，不会修改普通 `ysm-ragdoll.log`。

普通游戏实例没有工程路径属性时，日志写入游戏进程工作目录下同名文件夹。日志达到 8 MiB 时会
轮转为 `ysm-ragdoll.previous.log`。常规信息仍可在 Forge `logs/latest.log` 中搜索
`[ysmragdoll]`；性能行只写入本模组专属日志，避免污染 Forge 主日志。要强制指定诊断目录，可给 JVM 添加：

```text
-Dysmragdoll.projectDir=D:\path\to\project
```

正常创建时的重要日志顺序包括：

```text
ysmragdoll 初始化，协议版本 2
已在死亡事件线程立即冻结 YSM 模型
OpenYSM 几何匹配完成
YSM 物理骨架解析完成
已创建 JBullet 布娃娃
服务端捕获爆炸
客户端收到爆炸冲击
FPS窗口 10.0s: 实测平均=... 布娃娃=... 模组渲染平均=...ms
```

常见异常：

| 日志/现象 | 含义与检查方向 |
| --- | --- |
| `未加载 yes_steve_model` | 客户端没有加载兼容 YSM |
| `YSM 底层网格钩子尚未返回数据` | YSM 版本或混淆方法签名与 2.6.5 适配器不一致 |
| `Duplicate delegates` 后重试超时 | 0.5.21 及更早版本复用同一个临时顶点接收器导致；0.5.22 已修复此路径，若仍出现请附上完整异常堆栈 |
| `未定位到当前模型的 OpenYSM main.json` | 无法读取精确立方体，程序会使用骨骼枢轴估算 |
| `YSM 模型没有可识别的躯干骨骼` | 模型命名无法映射物理骨架，当前尸体保留静态快照 |
| `无法读取 Explosion 原始威力` | Forge 映射或第三方核心修改发生冲突；本次使用方块影响范围后备，不应崩溃 |
| `处理爆炸冲击失败` | 该次第三方爆炸被安全跳过；附带此日志和崩溃前后日志检查兼容性 |
| 爆炸没有推动尸体 | 检查高级设置指数是否为 0、尸体是否在半径两倍范围内、爆心和尸体之间是否有完整方块遮挡 |
| 模型与红/黄线框不重合 | 打开高级设置，分别检查碰撞偏移和渲染偏移；先恢复六轴为 0 排除旧配置 |
| 没有任何布娃娃 | 检查服务端是否安装、数量上限是否为 0、死亡包和模型捕获日志是否出现 |

## 构建

### 前置条件

- JDK 17；
- 首次构建可以访问 Gradle 分发镜像、Forge Maven 和 Maven Central；
- 工程包含 Gradle Wrapper；另外需要 `libs/openysm-2.6.5-forge+mc1.20.1.jar`（本地依赖，不纳入 Git）；
- 不需要在工程旁边保留 `OpenYSM-main` 源码目录。

Gradle Wrapper 会管理 Gradle 8.12。Windows 下直接运行 `gradlew.bat` 时，
Gradle 分发包和 Forge、Minecraft 映射、JBullet、vecmath 等依赖默认下载到工程内
`.gradle-home/`，不会占用系统盘的用户 Gradle 缓存；如已设置 `GRADLE_USER_HOME`，
则尊重调用者指定的目录。出于体积和分发边界考虑，ZIP 不复制这些缓存。
依赖下载完成后可使用工程内缓存重复离线构建。

PowerShell 5.1 / 7 构建命令：

```powershell
$env:JAVA_HOME = 'D:\Program Files\JDK-17'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\build.ps1 clean build
```

编译目标是 Java 17，GitHub Actions 使用 JDK 17。脚本尊重显式指定的
`JAVA_HOME`。未指定时，若工程 `.jdks/` 中有 JDK 17 且系统有 JDK 21，
则使用 JDK 21 运行 Gradle、JDK 17 编译，以兼容本机的 Java 17 loopback
问题；否则使用工程内 JDK 17。脚本不会自动下载 JDK，也不会将编译目标改为 21。
本机已具备上述环境时，可直接执行 `.\build.ps1 clean build`，无需设置 `JAVA_HOME`。
脚本运行后会恢复其修改的环境变量和工作目录。

### 代理构建

`build.ps1` 会把代理同时传给 Gradle Wrapper 和 Gradle/Maven 依赖解析。
优先读取当前 PowerShell 的代理环境变量；没有配置时，读取 Windows 系统
HTTP/HTTPS 代理，不写入仓库。PAC 自动配置需要手动指定 `GRADLE_PROXY_URL`。
仅支持 HTTP 代理端点（同样用于 HTTPS 请求），不将 SOCKS 端点冒充 HTTP 代理。

```powershell
$env:HTTPS_PROXY = 'http://127.0.0.1:7890'
$env:HTTP_PROXY = $env:HTTPS_PROXY
$env:NO_PROXY = 'localhost,127.0.0.1'
.\build.ps1 clean build
```

也可以使用带认证的统一代理地址：

```powershell
$env:GRADLE_PROXY_URL = 'http://user:password@proxy.example.com:8080'
.\build.ps1 test
```

如果代理密码包含 `@`、`:` 或其他 URI 特殊字符，请先进行 URL 编码。
解码后包含空白或 cmd 特殊字符的凭据会被拒绝，避免 Wrapper 参数解析错误。
直接运行 `gradlew.bat` 时，需要自行设置 `GRADLE_OPTS` 中的 Java
`http.proxyHost`、`http.proxyPort`、`https.proxyHost` 和 `https.proxyPort`；
日常构建建议使用 `build.ps1`。

主要任务：

| 任务 | 用途 |
| --- | --- |
| `gradlew.bat build` | 编译、处理资源、重混淆并生成两个 JAR |
| `gradlew.bat clean build` | 清理旧产物后完整构建，发布前使用 |
| `gradlew.bat test` | 验证骨骼与刚体绑定、捕获缓冲合并、玩家碰撞响应、设置布局和输入状态 |
| `gradlew.bat runClient` | 启动开发客户端，日志写入工程目录 |
| `gradlew.bat runServer` | 启动开发服务端 |

成功构建后：

```text
build/libs/ysmragdoll-0.5.26.jar
build/libs/ysmragdoll-0.5.26-all.jar
```

## 性能边界

- 模型反射、文件查找和解密只在首次遇到网格时进行，并使用弱键缓存；
- 所有布娃娃共享一个物理世界和方块缓存；
- 方块只扫描尸体附近且不主动加载区块；
- 数量上限最大 10，默认 2，达到上限严格淘汰最早尸体；
- 渲染暂停时重置物理帧时钟，避免恢复后追赶大量积压；
- 单帧物理追赶步数有上限，低帧率下优先避免整局卡死；
- 爆炸只在事件发生时遍历最多 10 具尸体及其主要刚体，不增加逐帧常驻扫描；
- 资源重载、断线、世界/维度卸载时释放所有刚体、约束和缓存。
- 每 10 秒汇总一次 FPS 与本模组渲染耗时，性能数据只写入专属日志。

10 只是配置允许的硬上限，不代表所有电脑和所有高复杂度模型都适合同时模拟 10 具尸体。实际使用应
根据帧率降低数量上限；调试碰撞箱也会增加线框绘制开销，排查结束后应关闭。

## 已知兼容边界

- 底层独立网格捕获针对 YSM 2.6.5 的混淆类和方法签名，YSM 更新后可能需要调整 Mixin 和反射适配；
- 当前物理是客户端视觉模拟，不是服务端权威实体，不能参与伤害、寻路、红石或原版实体碰撞；
- 不保存跨世界尸体，也不把玩家模型二进制写入存档；
- 模型骨骼名称差异过大时可能只能得到部分刚体，缺少躯干时退回静态快照；
- 头发、裙摆、披风和其他装饰骨骼目前没有独立刚体；
- 碰撞体采用旋转盒而不是逐三角形网格，这是稳定性与性能的有意取舍。
- 本次已修正骨骼与刚体绑定的坐标转换；真实模型仍需游戏内验证，非等比父级产生的剪切以及后备几何存在上述限制。
- 只有进入 Forge `ExplosionEvent.Detonate` 的爆炸会被识别；完全自定义且绕过原版流程的模组效果
  需要单独适配。
