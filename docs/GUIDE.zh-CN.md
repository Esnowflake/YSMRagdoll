# 使用与故障排查

[首页](../README.md) | [文档索引](README.md) | [反馈问题](https://github.com/Esnowflake/YSMRagdoll/issues)

## 安装与版本选择

按[首页兼容表](../README.md#下载与兼容性)选择游戏版本和加载器对应的 `-all.jar`，
并安装匹配平台的 YSM 2.6.5；Fabric 还需要 Fabric API。更新时退出游戏并移除旧安装包，
不要混装 Forge / Fabric 或不同 Minecraft 版本的 JAR。

Forge 1.20.1 提供 0.5.26 正式版；三平台 0.5.26-beta.1 为测试版，Fabric 完整游戏内验收尚未完成。
历史版本以 [Releases](https://github.com/Esnowflake/YSMRagdoll/releases) 为准。

## 打开设置与创建布娃娃

在 Minecraft 的按键绑定中为“打开YSM布娃娃设置”指定按键，返回游戏后按下该键。
默认未绑定快捷键。设置页面不暂停游戏。

玩家死亡时会尝试捕获当前已加载的 YSM 模型。也可在“高级”分类点击“创建一个布娃娃”，
无需死亡即可测试当前模型。这个按钮使用已保存的设置；修改参数后先点击“应用”。

“确定”保存并退出，“应用”保存并留在当前页，“取消”和 Esc 放弃尚未保存的数值修改。
创建、清理和牵引模式开关属于立即操作，不能通过“取消”撤销。

## 数量与清理

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 数量上限 | 2 | 可设 0–10；满额时移除最早的一具；设为 0 时清理并停止创建 |
| 存在时间 | 20 秒 | 0–10000 按秒计时，大于 10000 表示不按时间删除 |
| 手动清除 | 关闭 | 开启后忽略存在时间，可空手右键清除 |

“布娃娃管理”显示当前数量、每具布娃娃的剩余时间，并提供管理入口。
数量上限始终生效。切换世界/维度、断线或资源重载仍会清理布娃娃，
物理躯干低于 Y=-64 时也会清理；“永久”不表示跨世界保存。

## 木棍牵引

1. 在“测试”分类开启“牵引模式”。
2. 主手拿木棍，瞄准布娃娃肢体，按住使用键（默认右键）。
3. 滚轮向上推远、向下拉近；松开使用键释放。没有抓住时，松手后重新瞄准。

牵引距离为 1.5–12 方块，滚轮每格调整 0.5 方块。切换物品、打开界面或目标被清理会结束牵引。
开启模式且主手持木棍时会接管使用键；牵引仅影响本客户端的布娃娃。

| 牵引线力矩 | 效果 |
| --- | --- |
| 0 | 禁用牵引 |
| 1–99 | 有限力的柔性牵引；数值过低可能无法提起 |
| 100 | 刚性跟随，仍受方块碰撞阻挡 |

默认值为 70。牵引线弯曲反映目标与实际抓取点的滞后；跟上后逐渐拉直。

## 物理与调试设置

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 易推动指数 | 90 | 范围 0–100，调整玩家推动响应 |
| 地面摩擦力 | 20 | 范围 0–100，调整水平滑动衰减 |
| 爆炸推动指数 | 50 | 0 忽略爆炸，50 为标准强度，100 为两倍 |
| 显示物理碰撞箱 | 关闭 | 显示肢体物理线框，用于定位模型偏移 |
| 渲染 / 碰撞箱 XYZ 偏移 | 0 | 每轴 -4 至 4 方块，正常使用保持为 0 |
| 密集测试 | 关闭 | 输出高频诊断日志，仅在复现问题时临时开启 |

配置保存在游戏实例的 `config/ysmragdoll-client.toml`。升级时保留已有合法配置，
不会强制恢复新默认值。复杂模型、更多布娃娃、调试线框及密集日志会增加开销，
帧率较低时优先降低数量上限并关闭调试选项。

## 多人游戏

| 安装情况 | 结果 |
| --- | --- |
| 服务器安装；客户端安装本模组和 YSM | 客户端接收死亡信息并生成布娃娃 |
| 服务器安装；客户端未安装本模组 | 可加入，但看不到布娃娃 |
| 仅客户端安装 | 无法自动接收服务器死亡信息，可手动创建本地测试布娃娃 |

服务器广播死亡状态，不传输模型或逐帧物理状态。各客户端使用各自的模型缓存独立模拟，
所以同一布娃娃的姿态不保证一致。客户端和服务器应使用匹配版本。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 按键无法打开设置 | 确认已绑定快捷键，并在世界中关闭其他界面后尝试 |
| 没有生成布娃娃 | 确认 YSM 模型正常加载、数量上限不是 0；多人游戏检查服务器是否安装 |
| 能手动创建，死亡时不生成 | 优先检查服务器安装情况和死亡信息接收日志 |
| 只有静态模型 | 可能没有识别到模型躯干骨骼，无法初始化物理 |
| 模型与碰撞箱错位 | 先将渲染和碰撞六轴偏移恢复为 0，再检查模型骨骼及 YSM 版本 |
| 木棍无法牵引 | 确认牵引已开启、力矩不为 0、主手持木棍，且肢体未被地形遮挡 |
| 爆炸没有推动 | 检查推动指数、距离和遮挡；绕过原版爆炸流程的模组可能需要适配 |
| 更新后无法启动 | 检查是否混装重复 JAR、游戏版本/加载器不匹配或缺少依赖 |
| Fabric 表现异常 | Fabric 仍处于 Beta；请附对应版本、复现步骤和日志反馈 |

YSM 适配目标为 2.6.5，更新 YSM 后可能需要重新适配。
模型骨骼命名差异可能导致部分肢体无法识别；头发、裙摆等装饰没有独立刚体。
碰撞箱为旋转盒，不能与任意模型的外表面完全重合。

## 日志与反馈

普通实例在游戏进程工作目录下生成：

```text
ysm-ragdoll-logs/ysm-ragdoll.log
ysm-ragdoll-logs/ysm-ragdoll.previous.log
```

普通日志达到 8 MiB 时轮转。开启“密集测试”后还会生成
`ysm-ragdoll-logs/ysm-ragdoll-intensive.log`；排查完毕后关闭。
开发运行配置可能将这些文件放在工程目录中。

提交 [Issue](https://github.com/Esnowflake/YSMRagdoll/issues) 时，请提供：

- Minecraft、加载器、YSM、本模组版本，以及单人或多人环境。
- 复现步骤、预期结果和实际表现；模型问题可附截图或视频。
- 问题发生时段的模组日志和相关游戏异常堆栈。

分享前移除个人路径、服务器地址等无关信息；不要直接提交整套游戏目录或未经授权的模型资源。
开发者可继续阅读[技术架构](ARCHITECTURE.zh-CN.md)。
